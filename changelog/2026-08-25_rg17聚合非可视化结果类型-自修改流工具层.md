## 一、rg-17：聚合查询「非可视化结果类型」

**问题**（首轮回归抓出）：聚合查询（`GROUP BY bag_id COUNT(*)`）无行级时间语义，
但 `_check_start_end_ts` 强制 SELECT 含 start_ts/end_ts（可视化锚定），
聚合类问题永远过不了校验。

**修复**：
- `_is_aggregate_sql(sql)`：`GROUP BY` 或（顶层聚合函数 COUNT/SUM/AVG/MIN/MAX 且无行级时间列）→ 聚合
- `_query_two_round` / `generate_sql_two_round` 两条纠错路径：聚合 SQL 跳过 ts 校验
- `AgentResult.visualizable` / `AgentQueryResponse.visualizable` 字段透传（默认 True）
- 前端 `ResultTable`：`visualizable === false` 时行操作列显示「统计结果」替代可视化按钮
- golden `rg-17` 从 known_limitation 转为正常回归用例

## 二、自修改流工具层（②③⑤）

| 层 | 工具 | 功能 |
|---|---|---|
| ② 失败归因 | `tools/classify_regression_failures.py` | 读回归报告 JSON，失败 case 分类（route_masked 兜底掩盖 / sql_validation / semantic_deviation / forbidden_feature / infra）+ 每类修复方向建议 |
| ③ 修复生成 | `tools/suggest_synonyms.py` | 口语查询 + 目标 recipe → LLM 生成 5 条同义短语，输出 vector_synonyms.json 建议 diff（默认只打印人审，`--apply` 才并入） |
| ⑤ 用例转正 | `tools/add_golden_case.py` | badcase 一键追加 golden_queries.jsonl（id 唯一性校验防覆盖） |

至此自修改流五层齐全：① eval_nl2sql_regression（评测）→ ② classify（归因）→
③ suggest_synonyms（修复建议，人审）→ ④ 重跑回归（验证）→ ⑤ add_golden_case（沉淀）。

## 验证

- `_is_aggregate_sql` 单测：GROUP BY / 顶层纯计数 → 聚合；含 start_ts/end_ts 的行级 SQL → 非聚合
- 全量回归（26 条，DSW）：见本轮回归报告
