# 向量路由索引质量增强：口语化同义词表（hit@1 55%→90%）

> 日期：2026-08-20
> 范围：`agent/backend/app/core/vector_router.py`、`vector_synonyms.json`（新增）、`tools/eval_vector_recall.py`（新增）

## 问题

Phase 4a 向量路由对口语化查询召回失效：查"车子在我前面加塞插进来"，top3 返回
隧道入口/急刹/借道——完全不相干。两个根因：

1. **索引文本无语义**：templates.jsonl 的 nl 全是"自车切入：产线SQL直通模式(raw_sql)"
   这类模板元信息，噪声稀释了 embedding 信号；且 recipe id（英文 cut_in）不在索引文本里，
   英文查询完全匹配不到
2. **无口语化覆盖**：用户说"加塞/别我/鬼探头/裸左"，索引里只有书面语"自车切入/行人横穿/无保护左转"

## 修复

- **`vector_synonyms.json`**：68 组 recipe 的口语化同义短语（加塞/别我/鬼探头/裸左/下高速/
  转盘/一脚刹车等），数据文件、可随时增补
- **`_clean_nl()`**：剥离"产线SQL直通模式/raw_sql直通双模式/不经Block组装"等模板噪声
- **索引文本重排**：`清洗后语义描述 + recipe id + domain + 口语化同义词`
  （id 进文本，英文 "cut in" 类查询可命中）
- **force 重建先 clear()**：旧索引由外部脚本用不同 id 方案建立，不清理会新旧共存
  （同一 recipe 两份文本，搜索结果重复占位）
- 顺带修了 templates.jsonl 中 domain 为 list、同义词 value 为 list 的类型兼容

## 评测（tools/eval_vector_recall.py，20 条口语化查询）

| 指标 | Baseline（旧索引） | 增强后 |
|---|---|---|
| hit@1 | 11/20 (55%) | **18/20 (90%)** |
| hit@3 | 13/20 (65%) | **20/20 (100%)** |
| 完全未召回 | 7 条（加塞/别我/掉头/无保护左转/汇入/急弯…） | **0 条** |

剩余 2 条 hit@1 未命中均为语义歧义（"加塞"→ other_cutin_ego_yield vs obj_cut_in 均 0.28x 贴脸；
"变两条道"→ 连续变道 vs 两次变道掉头），hit@3 全部命中。

索引规模：93 系统模板 + 23 用户策略 = 116 条。重建命令：
`.venv/bin/python -c "import agent.backend.app.core.vector_router as vr; vr.load_from_templates(force=True)"`
（注意必须用模块引用而非 `from ... import _collection`，后者拿到的是 import 时的 None 快照。）
