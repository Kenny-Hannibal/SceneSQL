## 背景

上一轮改进清单（回归评测集 / 否定极性 / 策略版本管理 / LLM 单点 / resolve 冷查询 /
阈值失校 / 服务自启）的自动化落地，外加自修改流（评测→归因→修复→验证→沉淀）的地基。

## 交付内容

### 1. 端到端回归评测（自修改流地基）★
- `golden_queries.jsonl`：25 条标注问题，覆盖 recipe_exact / recipe_constrained（高速约束）/
  compound / colloquial / negation / aggregation / schema_presence / basic_contract 8 类
- `tools/eval_nl2sql_regression.py`：断言 route_method（防兜底路径掩盖——TableInfo 事故教训）
  + SQL 语义特征（must_contain / must_not_contain，大小写不敏感，不断言字符串相等）
  + validation_error；支持 `known_limitation` 断言（预期失败标记）
- 用法：DSW 上 `.venv/bin/python tools/eval_nl2sql_regression.py --report /tmp/regression_$(date +%F).json`
- **首轮全量：24/25 (96%)，耗时 567s**

### 2. 否定词护栏 + margin（concept_router Phase 4a）
- NL 含否定意图（不要/不用/排除/避免/除了/没有/非高速 等）→ 跳过向量短路，
  交 Round 2 LLM 结合完整问题生成（参考 SQL 模式下 LLM 看得到问题）
- top_k=2 + margin≥0.03 防贴脸误路由（`SCENESQL_VEC_MARGIN` 可配）
- 注意：Phase 1-3 关键词命中不受影响——参考模式下锚定方向由 LLM 校正，是期望行为

### 3. Phase 4a 阈值重校准
- 按同义词增强后分布收紧：正确命中集中 0.20-0.31、误报线 0.4+ → 阈值 0.35
  （`SCENESQL_VEC_THRESHOLD` 可配）

### 4. 用户策略启停（版本管理）
- user_strategies yaml 支持 `status: active|disabled`（缺省 active，存量无感）
- 路由 map / 向量索引只收 active（解决 无保护左转_v1~v4 版本互抢）
- API PUT /api/strategies/{name} 透传 status；前端策略面板加「启用/停用」按钮，
  停用行置灰 + 「已停用」徽章

### 5. LLM 单点降级链
- `_query_two_round` Round 1 调用失败 → 降级关键词路径（TagRouter），不再全瘫
  （generate-sql 端点级降级原本已有）；换模型走 OPENAI_BASE_URL/AGENT_MAIN_MODEL env，无需改码

### 6. resolve-bag-path 持久缓存 + 预取
- 内存 + 磁盘双层缓存（`/tmp/rosbag_path_cache.json`，TTL 24h，原子写），
  deploy --force 重启后仍秒回（内存缓存原本一重启就没）
- `/query` 返回后后台预取 ≤20 个缺 bag_path 的 bag_id——用户点可视化时冷查询
  5~30s 的等待已被消化在后台

### 7. BGE-M3 服务自启（用户选择手动方案）
- `/root/bin/start_bge_m3_serving.sh`：幂等一键拉起 vllm(GPU0:8101) + autossh 隧道
- 用户明确不注册 cron @reboot，重启后手动执行该脚本即可

## 首轮回归即发现的存量缺陷（已记录为待办）

**rg-17**：聚合查询（GROUP BY bag_id COUNT(*)）无行级时间语义，与
`_check_start_end_ts` 可视化锚定校验冲突，聚合类问题永远过不了校验。
正确解法：引入「非可视化结果类型」——聚合/统计类结果跳过锚定校验、
前端隐藏可视化按钮。已在 golden set 标记 known_limitation。
