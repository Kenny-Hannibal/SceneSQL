# 播包可视化卡顿根因修复：resolve-bag-path 缓存 + 线程池 + 弹窗先行

> 日期：2026-08-18
> 范围：`visualizer/backend/app/api/agent.py` + `visualizer/frontend/src/components/AgentPanel.jsx`

## 症状

点击「播包可视化」后页面长时间（5~30s）无任何反馈，像卡死。

## 根因（DSW 后端日志实证）

```
GET /api/agent/resolve-bag-path | status=200 | duration=32.075s
GET /api/agent/resolve-bag-path | status=200 | duration=25.907s
...
```

`/api/agent/resolve-bag-path` 每次请求都新建 `RosbagPathResolver`，走 dm_sdk 远程元数据查询
（ubm_vehicle_module_bin + 原始表，两次远程调用），**无缓存**，冷查询 5~30s。三重叠加：

1. **无缓存**：同一 bag 重复可视化每次都全量重查
2. **阻塞事件循环**：端点是 `async def` 但内部是同步阻塞调用，25s 内整个后端的所有请求
   （SSE、视频状态轮询等）全部被卡住
3. **前端零反馈**：`startVisualization` 旧逻辑是等 resolve 完成才打开 topic 弹窗，
   用户点击后页面长时间没有任何反应

与 2026-08-18 前端重构无关（视频流链路日志正常：spawn 0.2s、worker 干净退出）。

## 修复

### 后端 `app/api/agent.py`
- `resolve-bag-path` 加模块级 TTL 缓存（1 小时、上限 1000 条、仅缓存成功结果），
  同一 bag 重复可视化 25s → 毫秒级
- dm_sdk 同步阻塞调用包进 `asyncio.to_thread`，不再卡死事件循环

### 前端 `AgentPanel.startVisualization`
- **弹窗先行**：点击后立即打开 topic modal（loading 态「正在解析 bag 路径...」），
  resolve 在后台进行，用户始终有进度反馈
- 800ms 的连接释放等待改为条件等待：仅当确实有旧播放器/流在占用连接时才等，
  首次可视化省掉这 800ms

## 验证

- 后端 `py_compile` 通过；前端 build 通过
- DSW 部署后观察 `/tmp/rosbag_visualizer.log` 中 resolve-bag-path 的 duration：
  同一 bag_id 第二次起应 < 0.1s
