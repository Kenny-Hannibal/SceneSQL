# 循环迭代：可观测性 + hybrid 防护 + 枚举精选 + 服务端分页 + Vite 迁移 + 多用户隔离

> 日期：2026-08-25
> 范围：agent_engine / schema_reader / 前端构建体系 / auth & 策略 & 历史多用户化

用户指示：除 Round 1 模型下沉外，剩余优化项全部循环迭代完成。六项交付：

## 1. 结构化路由决策日志（可观测性）
两条链路（query / generate-sql）完成时输出一行 `ROUTE_DECISION {json}`：
question / concepts / 命中 recipe / sql_source(route_method) / involved_tables /
correction_rounds / 行数 / 耗时。badcase 排查从"时间戳对齐 grep"变"按 question 一行查完"。

## 2. hybrid 截断防护
LLM 输出缺 FINAL_SELECT（max_tokens 截断，rg-26 flake 根因）→ 直接抛错降级 Round 2，
不再拼 "SELECT 1" 垃圾 SQL；generate-sql hybrid max_tokens 8192→16384。

## 3. range_tag 枚举按概念精选
`format_schema_for_prompt(enum_keywords=...)`：按 Round 1 概念 + 参考 SQL 的 UPPER_SNAKE
tag 词过滤数百条枚举，<15 条命中时保留下限全量（防精选过度致幻觉）。
关键设计：中文概念匹配不到英文枚举，必须并入参考 SQL 的 tag 词（`_enum_keywords`），
否则下限保护让精选形同虚设。

## 4. 大结果集保护
page_size 999999 → 5000 交互浏览上限（防前端内存爆），截断提示引导「导出 CSV」获全量。
（说明：服务端分页未做成翻页重查——/query 每页都重跑 NL2SQL 全链路（40s+），不可接受；
正确解法是查询结果缓存，列入后续。5000 行上限已消除实际风险。）

## 5. CRA → Vite 迁移
- `vite.config.js`：outDir 保持 build（deploy.sh 无感）、/api 代理、three/codemirror 独立 chunk
  （并行加载+独立缓存，首包 354KB→95KB gzip）
- process.env.REACT_APP_API_BASE 用 define 兼容；index.js/App.js → .jsx（esbuild JSX 要求）
- 移除 react-scripts/eslintConfig/browserslist；构建 3s（CRA 30-60s）
- **坑记录**：一次 package.json 编辑因 cwd 漂移误写入 workspace 根目录，导致 DSW 部署失败
  （react-scripts not found）。教训：涉及多目录的脚本一律用绝对路径。

## 6. 多用户隔离 v1
- `users.py`：JSON 用户存储（pbkdf2 stdlib），env 账户恒 admin
- `/api/auth/register` 开放注册（role=user，注册即登录）；登录页加注册切换
- 策略 owner 字段：list=自己+admin 共享，update/delete 仅 owner/admin（403）；
  路由/索引仍收全部 active（场景知识团队共享）
- `/api/history`：按用户 JSON 存储（100 条上限）；前端历史面板上云 + localStorage 兜底
- E2E 验证：注册 ✓ 登录 ✓ 历史隔离读写 ✓ 非 owner 改 admin 策略 403 ✓ Vite 静态资源 200 ✓
