# 2026-08-13 Y型路口策略切换 v2 标签（地图分叉点 + 轨迹匹配）

**测试报告**: `test_reports/y-junction-v2-tag-test-report.md`

## 背景

旧标签 `topology_intersection_y_junction` 由 UBM 上游 TopologyConstraint 算子写入，
质量不佳（用户明确嫌弃）。新链路基于最上游地图信息重建 Y 型路口定义：

1. 从 OceanBase `infra_map_data.road_info` 提取「一分二」link 分叉点
   （toRoadIds 恰含 2 个后继 / reverseToRoadIds 反向；分支夹角 ≤60°；
   剔除 obj_info type=1 路口内 link）
2. 用各 bag `ego` 表经纬度（utm_x/utm_y 实为经/纬度）做轨迹匹配：
   30m 半径内 ≥2 个轨迹点判为经过
3. 批次 20260702 全量：15,460 bags，10,847 正样本，命中时刻回写各 bag
   `range_tag` 表，tag_name=`topology_intersection_y_junction_v2`，
   param 带 `source=ego_track_fork_match` 与 fork 明细，与上游旧标签完全隔离

## 变更内容

1. **「Y型路口」用户策略切换新标签** — `agent/backend/app/core/user_strategies/Y型路口.yaml`
   raw_sql 中 `WHERE tag_name` 由 `topology_intersection_y_junction` 改为
   `topology_intersection_y_junction_v2`，其余碎片合并/边界裁剪逻辑不变
2. **同名 recipe 同步** — `agent/backend/app/core/recipes/intersection_y_junction.yaml`
   同样切换 tag_name，保持策略与 recipe 一致

## 测试验证

- 数据层：100/100 正样本 bag 经策略 SQL 查出场景区间；10/10 负样本为空；
  全批扫描确认 v2 行 42,045 条、旧 tag 下无残留、UBM 上游行未动
- API E2E：登录 → batches 发现批次 → execute-sql 单 bag / 批次级均返回场景区间
- 详见 `test_reports/y-junction-v2-tag-test-report.md`
