## 2. 核心修复：3级 Recipe 匹配策略

### 问题描述

v0.2-beta 中，3个查询全部走了 LLM 而非 Recipe：
- "绿灯异常刹车" → sql_source: "llm"
- "前车急刹" → sql_source: "llm"
- "会车" → sql_source: "llm"

**根因**：Round1 LLM 返回的 concepts（如"绿灯刹车"、"异常刹车"）与 CONCEPT_RECIPE_MAP 中的中文 key（如"绿灯异常刹车"）不精确匹配。

### 修复方案

`concept_router.py` 中实现 3 级匹配：
1. **Phase 1: 精确匹配** — Round1 concepts 与 map key 完全一致
2. **Phase 2: 子串匹配** — concepts 子串包含 map key（或反之）
3. **Phase 3: NL 原文匹配** — 直接拿用户原始 NL 问题匹配 map key

### 测试结果

## 5. Bug 修复

### 5.1 nudge_borrowlane SQL 截断

- **问题**: YAML 中的 raw_sql 长度 14769，源文件 SQL 长度 15097，截断 328 字符
- **表现**: SQLite 报 `incomplete input` 错误
- **修复**: 从 db_py_rule/nudge_borrowlane.py 重新提取完整 SQL，重写 YAML
- **Commit**: 3dcf7c6

### 5.2 SQLite 3.37.2 json_extract 兼容性

- **问题**: `json_extract_string` 函数不存在于 SQLite 3.37.2
- **修复**: 使用 `json_extract` + 直接 CASE 比较（不带多余引号）
- **影响文件**: blocks/lane_change_detail.yaml, blocks/close_follow_detail.yaml

## 6. 已知问题

1. **借道避让执行耗时过长** — 15097 字符 SQL + 11878 DB 全扫描，执行时间 >2min，可能导致 SSE 流超时断开。建议：对 raw_sql Recipe 增加 `timeout` 配置或限制扫描 DB 数量。

2. **4个 Recipe SQL 源文件无结尾分号** — `ego_decel_during_lanechange`, `ego_overtake_catin_truck`, `front_hard_brake`, `truck_safe_cutin_ego` 的源 db_py_rule .py 文件中 SQL 不以 `;` 结尾。SQLite 可以执行但不够规范。建议：在提取脚本中自动追加 `;`。

3. **Phase 3 NL 原文匹配为最终兜底** — 当 Round1 LLM 完全无法识别概念时（如用户输入非常口语化的描述），仍可能无法命中 Recipe。需后续引入 embedding 相似度匹配作为 Phase 4。
