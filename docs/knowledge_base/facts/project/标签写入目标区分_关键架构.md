标签写入目标区分（关键架构）：
1. **SQLite range_tag表**：由 to_sqlite_db.py 写入，存放基础标签（如Cutin, CongestedFollow, STOPANDGO_FIRSTCARSTOPATREDLIGHT等），tag_name列直接存算子输出的label_id。SQLite中只有33个基础标签。
2. **cloud_tags JSON → 云端标签平台**：由 SQLQueryProcessor 执行 db_py_rule 下的规则生成。规则基于SQLite range_tag的param.name和param.sub_tag做映射重命名（如Cutin+CarCutin→Car_Cutin），产出cloud_tags格式（tag+start_time+end_time，时间戳×1e9转纳秒）。
3. **all_tags_convert.py**：是db_py_rule规则之一，它查SQLite的range_tag表，做CASE WHEN重命名映射，产出的新tag_name（如Run_RedLight, GreenLightNotProceeding, Traffic_Intersection, Car_Cutin, VruPed_Cross等）**只存在于cloud_tags JSON中，不写入SQLite**。
4. **SceneSQL查询的是SQLite**：所以SceneSQL的schema_dictionary只需要包含SQLite range_tag中存在的33个基础标签。db_py_rule中映射出的云端标签不在SQLite中，SceneSQL查不到。

结论：db_py_rule目录下的标签是"云端标签"，不是SQLite标签。sync_schema.py扫描db_py_rule确实是噪音——这些标签对SceneSQL的SQL查询没有意义，因为它们根本不在SQLite DB中。
